# AAS VPN

Собственный сервис для защищённых подключений: AmneziaWG, портал пользователей, AdGuard Home и управление маршрутами. Вход пользователей — по телефону через Zvonok, администратора — по общей учётной записи wg-easy с поддержкой TOTP.

## Установка

Нужны Debian 12+/Ubuntu 22.04+, модуль ядра AmneziaWG, root и два домена с A-записями на сервер. Caddy использует TCP 80/443, AmneziaWG — UDP 443 и 1234.

```bash
git clone https://github.com/NikoVonLas/aas-vpn.git
cd aas-vpn
cp .env.example .env
nano .env
sudo ./scripts/deploy.sh
```

В `.env` заполните:

| Параметры | Что указать |
| --- | --- |
| `VPN_DOMAIN`, `PORTAL_DOMAIN` | Домены панели wg-easy и портала |
| `VPN_SITE_ADDRESS`, `PORTAL_SITE_ADDRESS` | Те же домены для Caddy |
| `COOKIE_DOMAIN` | Общий домен cookie, например `.example.com` |
| `ZVONOK_PUBLIC_KEY`, `ZVONOK_CAMPAIGN_ID`, `ZVONOK_DIAL_NUMBERS` | Ключ, ID кампании «Звонок на проверочный номер» и номера подтверждения |

До первого deploy проверьте имя внешнего интерфейса в `config/sing-box.json` (по умолчанию `ens3`). Скрипт устанавливает стек в `/opt/aas-vpn` (другой путь: `AAS_INSTALL_DIR`), собирает образы и настраивает службы и сеть хоста. Используются wg-easy **15.4.0** и sing-box **1.13.15**; IPv6 отключён.

## Первый запуск

1. Откройте `https://VPN_DOMAIN` и завершите мастер wg-easy. Укажите порт клиента `443`, DNS `10.42.42.44` и параметры AmneziaWG.
2. Настройте AdGuard через туннель `ssh -L 3000:127.0.0.1:3000 root@SERVER` и страницу `http://localhost:3000`. DNS: `0.0.0.0:53`; upstream: `10.42.42.1:5353`, `:5354`, `:5355`, `:5356`; режим `parallel`, timeout `5s`.
3. Войдите в `https://PORTAL_DOMAIN/admin/login` с логином, паролем и TOTP от wg-easy. Синхронизация учётной записи занимает до 15 секунд.
4. Добавьте телефоны пользователей и лимиты устройств. Пользователи входят на `https://PORTAL_DOMAIN`, подтверждают номер звонком и получают конфиг или QR-код.

## Управление

- **Пользователи** (`/admin`): доступ, лимиты и управление устройствами любого аккаунта без отдельного входа по телефону.
- **RU-выходы** (`/admin/ru-exits`): загрузка и редактирование WireGuard-конфигов, выбор дефолта и назначения устройствам. Сохранённый конфиг виден администратору в текстовом поле; загруженный файл сразу появляется там же для правок. Существующий `wg-ru` регистрируется автоматически; для нового выхода загрузите конфиг и выберите его по умолчанию.
- **Маршрутизация** (`/admin/routing`): правила для доменов и IPv4/CIDR. Начальные правила берутся из серверного JSON, последующие изменения вносятся через портал.

Смена выхода пользователем по умолчанию запрещена. Отзыв разрешения сбрасывает его назначения, сохраняя назначения администратора. При отказе выбранного выхода используется доступный дефолт; если оба недоступны, соответствующий трафик не проходит. Изменения применяются на сервере без переимпорта клиентских конфигов, но текущие соединения могут прерваться. Устройства, созданные напрямую в wg-easy, портал не импортирует.

Для Keenetic есть парные примеры: [VPS](examples/wg-ru-keenetic-vps.conf.example) и [роутер](examples/wg-ru-keenetic-router.conf.example). Входящий WireGuard-порт VPS должен быть открыт.

## Обновление и восстановление

Обновляйте из отдельной копии репозитория, а не из `/opt/aas-vpn`: запустите в ней `sudo ./scripts/deploy.sh`. Скрипт сохранит серверные `.env`, `config/` и `data/`, создаст согласованный бэкап с краткой остановкой сервисов и пересоберёт образы.

```bash
cd /opt/aas-vpn
sudo ./scripts/backup.sh
sudo ./scripts/rollback.sh /opt/aas-vpn/backups/YYYYMMDDTHHMMSSZ
```

Откат восстанавливает образы и данные вместе; используйте только бэкап с файлом `COMPLETE`. Настройки и ключи находятся в persistent volumes. Не добавляйте `.env`, реальные конфиги и бэкапы в Git.

## Проверки и внешний Caddy

Проверка вёрстки на телефоне, планшете и компьютере — [скриншотные тесты Playwright](tests/ui/README.md).

`./scripts/validate.sh` проверяет конфигурацию; `docker compose ps` показывает состояние сервисов. Для тестов установите зависимости из `portal/requirements.txt` и `tests/requirements.txt`, выполните `npm ci --ignore-scripts --prefix portal`, затем `./scripts/validate.sh --tests` (нужны Python, Node.js и Compose CLI). Сетевые сценарии — в [tests/LINUX.md](tests/LINUX.md). Перед релизом обязателен успешный SonarQube всего `main`, включая старый код; требования — в [AGENTS.md](AGENTS.md).

За существующим Caddy задайте в серверном `.env` `COMPOSE_FILE=compose.yml:compose.edge.yml`, адреса сайтов со схемой `http://`, loopback-порты `CADDY_HTTP_PUBLISH`/`CADDY_HTTPS_PUBLISH` и имя общей сети `VPN_NETWORK_NAME`. Серверные конфиги overlay: `data/adguard/` и `data/sing-box/config.json`. При подключении существующих данных укажите имена volumes из `.env.example`.
